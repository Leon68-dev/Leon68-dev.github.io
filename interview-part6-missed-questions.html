1. У чому різниця між `Tuple` та `ValueTuple` у C#?

↑ До змісту
Коротка суть: `System.Tuple` — це посилальний клас (Heap, алокація пам'яті, незручні імена `Item1`, `Item2`). `System.ValueTuple` (C# 7+) — це структура на стеку з підтримкою іменованих полів `(int Id, string Name)` та синтаксису деконструкції.

Порівняльна таблиця:

Характеристика System.Tuple System.ValueTuple
Тип пам'яті Reference Type (Class в купі) Value Type (Struct на стеку)
Мутабельність Незмінний (Read-only) Змінний (поля відкриті)
Синтаксис назв полів Тільки Item1, Item2 Довільні: (int Id, string Title)
Деконструкція Не підтримується з коробки var (id, title) = GetData();
Підступні питання на співбесіді:
П: Як компілятор зберігає імена полів `(int Id, string Name)` у згенерованому IL-коді?

В: На рівні байт-коду IL полів із кастомними іменами не існує — вони завжди називаються `Item1` та `Item2`. Компілятор додає до методів чи властивостей службовий атрибут `[TupleElementNames(new[] {"Id", "Name"})]`, завдяки якому IDE та компілятор C# знають їхні псевдоніми під час збірки.

2. Що таке атрибути в C#? Як створити власний атрибут та обмежити його використання?

↑ До змісту
Коротка суть: Атрибути — це декларативні метадані, які «прикріплюються» до класів, методів чи полів та зберігаються у збірці. Їх можна читати через рефлексію в рантаймі або аналізувати source generator'ами під час компіляції.

Створення власного атрибута:

// 1. Успадковуємося від System.Attribute
// 2. Обмежуємо область дії атрибута за допомогою [AttributeUsage]
[AttributeUsage(AttributeTargets.Class | AttributeTargets.Method, AllowMultiple = false)]
public class EndpointRoleAttribute : Attribute
{
    public string RequiredRole { get; }

    public EndpointRoleAttribute(string role) => RequiredRole = role;
}

// Застосування:
[EndpointRole("Admin")]
public class AdminController { }

// Читання через рефлексію:
var attr = typeof(AdminController).GetCustomAttribute<EndpointRoleAttribute>();
Console.WriteLine(attr?.RequiredRole); // Admin
Підступні питання на співбесіді:
П: Чому конструктор атрибута приймає лише константи або `typeof()`?

В: Оскільки екземпляри атрибутів формуються під час компіляції і серіалізуються напряму в таблиці метаданих збірки (.dll), їх параметри повинні бути обчислені на етапі збірки (compile-time constants: примітиви, рядки, enum або типи).

3. LINQ: Різниця між `First`, `FirstOrDefault`, `Single` та `SingleOrDefault`?

↑ До змісту
Коротка суть: `First` бере перший і зупиняє пошук. `Single` перевіряє ВСЮ колекцію до кінця, щоб гарантувати відсутність дублікатів (кидає виняток, якщо знайдено більше одного елемента!).

Таблиця поведінки методів:

Метод Колекція порожня (0) Рівно 1 елемент Більше 1 елемента (>1)
First() InvalidOperationException Повертає елемент Повертає перший знайдений
FirstOrDefault() Повертає null (або default) Повертає елемент Повертає перший знайдений
Single() InvalidOperationException Повертає елемент InvalidOperationException (Помилка!)
SingleOrDefault() Повертає null (або default) Повертає елемент InvalidOperationException (Помилка!)
Підступні питання на співбесіді:
П: Який SQL генерує EF Core для `First()` у порівнянні з `Single()`?

В: Метод `First()` генерує `SELECT TOP(1) ...`, оскільки СУБД достатньо повернути один перший рядок. Метод `Single()` генерує `SELECT TOP(2) ...`, тому що ORM зобов'язана перевірити наявність другого рядка, щоб викинути `InvalidOperationException` у разі дублювання записів.

4. Що таке індексатори (Indexers) у класах? Навіщо потрібні?

↑ До змісту
Коротка суть: Дозволяють звертатися до екземпляра вашого класу за числовим або рядковим індексом за допомогою квадратних дужок `myObj[0]` або `myObj["key"]`, як до масиву чи словника.

Приклад реалізації:

public class KeyValueCache
{
    private readonly Dictionary<string, string> _storage = new();

    // Індексатор оголошується через ключове слово 'this'
    public string this[string key]
    {
        get => _storage.TryGetValue(key, out var val) ? val : null;
        set => _storage[key] = value;
    }
}

// Використання:
var cache = new KeyValueCache();
cache["theme"] = "dark"; // Працює як словник
Console.WriteLine(cache["theme"]);
Підступні питання на співбесіді:
П: Як індексатор компілюється в IL-байткод?

В: Він перетворюється на звичайні методи `get_Item(key)` та `set_Item(key, value)`, а сам клас маркується атрибутом `[DefaultMember("Item")]`. У мовах, які не підтримують синтаксис квадратних дужок (наприклад, старий VB), звернення відбувається саме через виклик `obj.get_Item(...)`.

5. Двобічно зв'язаний список `LinkedList`: будова та відмінність від `List`.

↑ До змісту
Коротка суть: У `List` елементи лежать неперервним масивом у пам'яті (швидкий індекс $O(1)$, але вставка в середину займає $O(N)$). `LinkedList` складається з окремих об'єктів-вузлів `LinkedListNode` з покажчиками `Next` та `Previous`. Вставка поруч із відомим вузлом займає $O(1)$.

Плюси та мінуси `LinkedList`:

  • Переваги: Миттєва вставка або видалення вузла з будь-якого місця списку за $O(1)$ без зсуву сусідніх елементів у пам'яті та без необхідності перевиділення внутрішнього масиву.
  • Недоліки: Немає доступу за індексом `list[i]` — щоб знайти 100-й елемент, треба послідовно пройти 99 вузлів ($O(N)$). Вузли розкидані по всій купі, що ламає кеш процесора (CPU Cache Misses) та вимагає додаткових байтів пам'яті на кожен елемент під покажчики.
Підступні питання на співбесіді:
П: Чому на практиці `List` майже завжди швидший за `LinkedList` навіть при частих вставках?

В: Через локальність даних у кеші CPU (Cache Locality). Елементи `List` лежать у пам'яті щільно один за одним, і процесор зчитує їх цілими кеш-лініями по 64 байти наперед. У `LinkedList` кожен вузол — це окремий об'єкт у купі, тому перехід за вказівником викликає постійні Cache Misses.

6. Що таке рефлексія (`System.Reflection`)? Які її плюси, мінуси та вплив на швидкодію?

↑ До змісту
Коротка суть: Механізм дослідження метаданих типів під час виконання програми: отримання списку приватних полів, методів та створення екземплярів через `Activator.CreateInstance`. Рефлексія суттєво повільніша за звичайний виклик і ламає Native AOT тримінг.

Чому рефлексія повільна:

  1. JIT-компілятор не може застосувати оптимізації (інлайнінг методів, розгортання циклів, девіртуалізацію).
  2. Відбуваються постійні перевірки прав доступу (security checks) та валідація типів аргументів у runtime.
  3. При виклику методів через MethodInfo.Invoke(obj, params) для значущих типів відбувається масовий Boxing/Unboxing параметрів у масив object[].

Сучасна альтернатива: У сучасному .NET 8/9 рефлексію замінюють на Source Generators (генерація C# коду під час компіляції), що дає максимальну швидкість без втрати гнучкості.

Підступні питання на співбесіді:
П: Як прискорити виклики методів через рефлексію у сотні разів, якщо тип відомий лише в рантаймі?

В: Використати компіляцію виразів `Expression.Compile()` або `Delegate.CreateDelegate()`. Знайдений метод один раз загортається у строго типізований делегат, після чого всі наступні виклики виконуються з нативною швидкістю прямого виклику.

7. Як JIT-компілятор генерує код для узагальнень (Generics): різниця для Value Types та Reference Types?

↑ До змісту
Коротка суть: Для кожного Value Type створюється окрема унікальна копія машинного коду (спеціалізація під розмір структури). Для ВСІХ Reference Types використовується одна спільна копія машинного коду, оскільки розмір покажчика завжди однаковий.

Деталі роботи JIT:

  • Значущі типи (List<int> vs List<double>): Структури мають різний розмір (int — 4 байти, double — 8 байт). JIT-компілятор створює окремий бінарний машинний код під кожен значущий тип. Це гарантує максимальну швидкодію без boxing'у, але збільшує розмір коду в оперативній пам'яті (Code Bloat).
  • Посилальні типи (List<string> vs List<User>): Оскільки будь-який посилальний тип представлений у пам'яті звичайним покажчиком (адресою розміром 8 байт на x64 системі), JIT компілює машинний код рівно один раз, і всі класи ділять між собою одну реалізацію методів.
Підступні питання на співбесіді:
П: Що таке канонічний тип `__Canon` у контексті JIT-компіляції узагальнень?

В: `System.__Canon` — це внутрішній службовий тип CLR. Усі спеціалізації узагальненого класу для Reference-типів ділять між собою один єдиний набір машинних інструкцій, згенерований для типу `__Canon`.

8. Як правильно створити власний виняток (Custom Exception) у .NET?

↑ До змісту
Коротка суть: Успадкуватися від `Exception`, додати суфікс `Exception` до назви класу та реалізувати 3 стандартні базові конструктори.

Еталонна реалізація:

public class OrderNotFoundException : Exception
{
    public int OrderId { get; }

    // 1. Порожній конструктор
    public OrderNotFoundException() : base() { }

    // 2. Конструктор із повідомленням
    public OrderNotFoundException(string message) : base(message) { }

    // 3. Конструктор з inner exception (для обгортання інших помилок)
    public OrderNotFoundException(string message, Exception inner) : base(message, inner) { }

    // Кастомний конструктор із бізнес-даними:
    public OrderNotFoundException(int orderId) 
        : base($"Замовлення з ID #{orderId} не знайдено.")
    {
        OrderId = orderId;
    }
}
Підступні питання на співбесіді:
П: Чому в .NET 8+ більше не потрібно додавати конструктор серіалізації `protected CustomException(SerializationInfo info, StreamingContext context)`?

В: Технологія `BinaryFormatter` була визнана небезпечною та повністю відключена за замовчуванням у сучасному .NET. Відповідно, підтримка бінарної серіалізації для винятків застаріла (obsolete).

9. У чому принципова різниця між Процесом (Process) та Потоком (Thread)?

↑ До змісту
Коротка суть: Процес — це ізольований екземпляр запущеної програми з власним захищеним віртуальним адресним простором. Потік — це найменша одиниця виконання CPU всередині процесу. Усі потоки одного процесу ділять спільну купу (Heap).

Порівняння:

  • Процес (Process): Повна ізоляція пам'яті. Падіння одного процесу не впливає на інші процеси ОС. Комунікація між процесами (IPC) повільна (іменовані канали, сокети, файли).
  • Потік (Thread): Має власний стек (~1 МБ), але ділить пам'ять купи (Heap), дескриптори файлів та мережеві з'єднання з усіма іншими потоками свого процесу. Перемикання контексту між потоками одного процесу набагато швидше, але спільна пам'ять вимагає синхронізації (lock, семафори), інакше виникає стан гонитви (Race Condition).
Підступні питання на співбесіді:
П: Що саме скидається під час перемикання контексту між процесами, чого не відбувається при перемиканні між потоками одного процесу?

В: При перемиканні між процесами операційна система змушена перемикати таблиці сторінок віртуальної пам'яті (CR3 регістр у x86/x64). Це повністю інвалідує буфер асоціативної трансляції CPU (TLB — Translation Lookaside Buffer), що веде до тимчасового падіння швидкодії доступу до RAM.

10. Що таке рекурсія? Чому виникає `StackOverflowException` і як його уникнути?

↑ До змісту
Коротка суть: Рекурсія — виклик методом самого себе. Вимагає обов'язкової умови виходу (Base Case). Кожен виклик виділяє новий фрейм на стеку. При занадто глибокій рекурсії стек переповнюється, і процес аварійно падає.

Чому StackOverflowException не можна перехопити через catch:

Починаючи з .NET 2.0, переповнення стека є фатальною помилкою CLR. Рантайм негайно завершує весь процес без виконання блоків catch або finally, оскільки для обробки винятку банально не залишилося вільної пам'яті стека!

Як уникнути: Переписати алгоритм з рекурсивного на ітеративний (використовуючи звичайний цикл while та колекцію Stack<T> у купі Heap).

Підступні питання на співбесіді:
П: Чи гарантує компілятор C# оптимізацію хвостової рекурсії (Tail Call Optimization)?

В: Ні! Компілятор C# не гарантує перетворення хвостової рекурсії на цикл (хоча в IL є інструкція `tail.`). Для збереження повноти трасування стеку безпеки (Security Stack Walk) JIT-компілятор у більшості випадків створює повноцінний стековий фрейм.

11. Що таке Cohesion (зв'язність) та Coupling (зачеплення)? Який ідеальний баланс?

↑ До змісту
Коротка суть: Золотий стандарт архітектури: **High Cohesion** (висока внутрішня зв'язність) та **Loose Coupling** (слабке зовнішнє зачеплення).

Розбір термінів:

  • Cohesion (Зв'язність усередині класу): Показує, наскільки тісно методи та поля одного класу пов'язані єдиною метою.
    • Низька (погано): Клас робить усе підряд (робота з базою, відправка листів, валідація, рендеринг звіту).
    • Висока (добре): Клас вирішує лише одну конкретну бізнес-задачу (Single Responsibility Principle).
  • Coupling (Зачеплення між різними класами): Показує ступінь залежності модулів один від одного.
    • Сильне (погано): Клас А напряму викликає приватні деталі класу Б через new ConcreteClass(). Зміна класу Б ламає клас А.
    • Слабке (добре): Класи спілкуються через інтерфейси або події (Dependency Inversion). Будь-який клас можна замінити без зміни інших.
Підступні питання на співбесіді:
П: Що стверджує Закон Деметри (Law of Demeter) і як він пов'язаний із Coupling?

В: Принцип "найменшої обізнаності": модуль повинен спілкуватися лише зі своїми безпосередніми сусідами. Ланцюжки викликів на зразок `order.Customer.Address.City.ZipCode` створюють сильне зачеплення (tight coupling) з усією структурою вкладених класів.

12. Навіщо балансувати дерева пошуку? Властивості ідеальної хеш-функції.

↑ До змісту
Коротка суть: Незбалансоване бінарне дерево деградує у звичайний лінійний список $O(N)$. Балансування (АВЛ, Червоно-чорні дерева) гарантує логарифмічний пошук $O(\log N)$. Ідеальна хеш-функція: швидка, детермінована та рівномірно розкидає значення по кошиках.

Властивості хорошої хеш-функції (`GetHashCode`):

  1. Детермінізм: Для однакових вхідних значень завжди повертає однаковий цілочисельний хеш протягом усього часу роботи програми.
  2. Рівномірний розподіл (Uniform distribution): Мінімізує колізії, розподіляючи ключі по всьому діапазону від int.MinValue до int.MaxValue.
  3. Швидкість обчислення: Повинна виконуватися за лічені такти процесора, інакше вставка в `Dictionary` стане вузьким місцем.
Підступні питання на співбесіді:
П: Яке збалансоване дерево використовується у вбудованому класі `SortedDictionary` у .NET?

В: Під капотом `SortedDictionary` реалізований як червоно-чорне дерево (Red-Black Tree), що гарантує складність вставки, видалення та пошуку $O(\log N)$.

13. Які 5 типів фільтрів існують в ASP.NET Core? Строгий порядок їх виконання.

↑ До змісту
Коротка суть: Ланцюжок фільтрів спрацьовує всередині MVC-пайплайну в строгому порядку: 1. Authorization → 2. Resource → 3. Action → 4. Exception → 5. Result.

Порядок виконання:

  1. Authorization Filters: Виконуються першими. Перевіряють, чи має користувач доступ до дії (наприклад, [Authorize]). Якщо ні — негайно переривають запит (401 або 403).
  2. Resource Filters: Огортають увесь наступний конвеєр (включаючи Model Binding). Ідеальні для реалізації кешування всієї відповіді або зміни поведінки завантаження тіла запиту.
  3. Action Filters: Спрацьовують безпосередньо до та після виконання методу контролера. Мають доступ до вхідних аргументів методу.
  4. Exception Filters: Перехоплюють необроблені винятки, що виникли під час роботи Action або Action Filters.
  5. Result Filters: Спрацьовують до та після рендерингу або серіалізації фінального результату IActionResult.
Підступні питання на співбесіді:
П: Чому `ExceptionFilter` не перехоплює помилки, які виникають усередині `ResultFilter` або під час запису відповіді в сокет?

В: `ExceptionFilter` охоплює виключно виконання `ActionFilter` та коду самого Action-методу. Якщо помилка виникає під час рендерингу результату у `ResultFilter`, її зможе перехопити лише глобальний `ExceptionHandlerMiddleware` у конвеєрі.

14. У чому принципова різниця між JWT токеном та Bearer токеном?

↑ До змісту
Коротка суть: `Bearer` — це назва схеми авторизації в HTTP-заголовку. `JWT` — це формат представлення даних самого токена.

Пояснення:

Коли клієнт робить запит, він передає заголовок:

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
  • Bearer (Пред'явник): Схема протоколу OAuth 2.0 (RFC 6750). Вона каже серверу: «Той, хто тримає (bears) цей токен, має вказані права». При цьому токен під схемою Bearer взагалі не зобов'язаний бути JWT — це може бути простий випадковий рядок (Reference Token або Opaque Token), збережений у Redis!
  • JWT (JSON Web Token): Конкретний відкритий стандарт (RFC 7519), який описує, як закодувати JSON-структуру (Claims) у безпечний Base64-рядок із цифровим підписом.
Підступні питання на співбесіді:
П: Коли краще обрати Reference (Opaque) токен замість JWT?

В: Коли потрібне миттєве відкликання токена або коли Claims містять забагато даних, роздуваючи розмір кожного HTTP-заголовка. Тоді токен є просто випадковим ідентифікатором у Redis, а сервер перевіряє його за $O(1)$.

15. Що таке CORS (Cross-Origin Resource Sharing)? Як працює попередній запит `OPTIONS` (Preflight)?

↑ До змісту
Коротка суть: Політика безпеки браузера (Same-Origin Policy), яка забороняє JavaScript з сайту А відправляти запити на API сайту Б, якщо домен, протокол або порт відрізняються. Preflight запит `OPTIONS` перевіряє дозвіл сервера перед відправкою реального запиту.

Як працює Preflight:

  1. Якщо запит не є «простим» (наприклад, містить кастомний заголовок Authorization або метод PUT/DELETE), браузер автоматично відправляє легкий запит методом OPTIONS на той самий URL.
  2. Браузер запитує: «Чи дозволено сайту frontend.com відправити POST-запит із заголовком Authorization?»
  3. Сервер відповідає заголовками: 
    Access-Control-Allow-Origin: https://frontend.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Authorization, Content-Type
  4. Якщо сервер підтвердив дозвіл — браузер відправляє реальний запит. Якщо ні — браузер блокує відповідь із помилкою CORS у консолі.
Підступні питання на співбесіді:
П: Чому POST-запит із `Content-Type: application/json` завжди викликає Preflight OPTIONS, а `text/plain` — ні?

В: За специфікацією CORS тільки три типи вмісту вважаються "простими" (Simple Requests): `text/plain`, `multipart/form-data` та `application/x-www-form-urlencoded`. Будь-який інший тип, включаючи `application/json`, браузер зобов'язаний попередньо узгодити з сервером через Preflight.

16. Що таке концепція SPA (Single Page Application)?

↑ До змісту
Коротка суть: Веб-додаток, який завантажує один єдиний HTML-документ при першому візиті. Переходи між сторінками відбуваються без перезавантаження всієї сторінки за допомогою клієнтського роутингу (React, Angular, Vue, Blazor WebAssembly).

SPA проти Традиційного MPA (Multi-Page App):

  • MPA (Razor Pages, ASP.NET MVC): Кожен клік по посиланню робить повний перехід на сервер, сервер рендерить усю HTML-сторінку заново та відправляє її через мережу.
  • SPA: Браузер завантажує бандл JS/WASM один раз. При зміні URL JavaScript динамічно перемальовує лише потрібну частину сторінки (DOM), звертаючись до бекенду суто за чистими JSON-даними через REST API або gRPC-Web.
Підступні питання на співбесіді:
П: Яка головна проблема чистого SPA з погляду SEO та як її вирішують сучасні фреймворки?

В: Пошукові роботи пошуковиків отримують порожній HTML-каркас (`

`) без контенту, оскільки рендеринг виконується клієнтським JS. Вирішується через Server-Side Rendering (SSR) або Server Components (Next.js, Nuxt або Blazor SSR у .NET 8).

17. Minimal API проти класичних MVC-контролерів в ASP.NET Core: плюси та мінуси.

↑ До змісту
Коротка суть: Minimal API (C# 10+) відкидає громіздкий оверхед MVC-пайплайну (фільтри, контролери, рефлексія), забезпечуючи вищу пропускну здатність та менше споживання RAM.

Порівняння підходів:

// Minimal API: прямий мапінг ендпоінта в Program.cs
app.MapGet("/users/{id}", async (int id, AppDbContext db) => 
    await db.Users.FindAsync(id) is User u ? Results.Ok(u) : Results.NotFound());
  • Переваги Minimal API:
    • Вища швидкість старту та продуктивність (RPS приблизно на 15–20% вище за контролери).
    • Ідеально підходить для мікросервісів та AWS Lambda / Azure Functions.
    • Підтримує Native AOT (компіляція в нативний двійковий файл без включення всього рантайму).
  • Коли обирати контролери: Великі Enterprise-моноліти з десятками уніфікованих фільтрів, складними валідаціями та десятками дієслів на один ресурс.
Підступні питання на співбесіді:
П: За рахунок чого Minimal API працює швидше за Controller-based API?

В: Minimal API не створює екземпляр контролера на кожен запит (нуль рефлексії через `IControllerFactory`), оминає фільтри дій MVC та використовує скомпільовані під час старту виклики `RequestDelegate`.

18. Нормальні форми реляційних баз даних (1NF, 2NF, 3NF). Навіщо роблять денормалізацію?

↑ До змісту
Коротка суть: Нормалізація усуває надлишкове дублювання даних та аномалії оновлення. Денормалізація — це свідоме повернення надлишковості для прискорення складних SELECT-запитів без важких JOIN'ів.

Три класичні нормальні форми:

  1. 1NF (Перша нормальна форма): Усі значення колонок повинні бути атомарними (неподільними). В одній комірці не може бути списків значень на зразок "Київ, Львів, Одеса". Рядки мають бути унікальними (наявність PK).
  2. 2NF (Друга нормальна форма): Відповідає 1NF + будь-яка неключова колонка повинна залежати від усього складеного первинного ключа цілком, а не від його частини.
  3. 3NF (Третя нормальна форма): Відповідає 2NF + відсутність транзитивних залежностей (неключові колонки повинні залежати ТІЛЬКИ від первинного ключа, а не одна від одної).

Навіщо потрібна денормалізація: Якщо для генерації одного звіту доводиться робити JOIN по 8 таблицях, це перевантажує дискову підсистему БД. Розробники додають дублюючі поля (наприклад, зберігають пораховану суму замовлення `TotalAmount` прямо в таблиці `Orders`), щоб читати рядок миттєво.

Підступні питання на співбесіді:
П: Які три аномалії даних вирішує нормалізація таблиць?

В: 1) Аномалію вставки (неможливо додати сутність без прив'язки до іншої); 2) Аномалію видалення (видалення одного запису випадково знищує іншу потрібну сутність); 3) Аномалію оновлення (зміна адреси клієнта вимагає оновлення тисяч рядків замовлень, інакше дані розсинхронізуються).

19. Оптимістичне блокування (Optimistic Concurrency) та `DbUpdateConcurrencyException` в EF Core.

↑ До змісту
Коротка суть: Замість блокування рядка на час редагування, сутність отримує версійну колонку `RowVersion`. Якщо хтось встиг змінити рядок паралельно, EF Core викидає `DbUpdateConcurrencyException`.

Як це реалізувати:

public class Account
{
    public int Id { get; set; }
    public decimal Balance { get; set; }

    [Timestamp] // Атрибут версії рядка для MS SQL (або IsRowVersion() у Fluent API)
    public byte[] RowVersion { get; set; }
}

Що генерує EF Core при збереженні:

UPDATE Accounts SET Balance = @p0 
WHERE Id = @p1 AND RowVersion = @originalRowVersion;

Якщо між читанням та записом інший користувач змінив баланс, значення RowVersion у базі автоматично змінилося тригером СУБД. Запит UPDATE оновить рівно 0 рядків. EF Core бачить, що жоден рядок не оновився, і викидає виняток DbUpdateConcurrencyException, не дозволяючи тихо затерти чужі фінансові дані.

Підступні питання на співбесіді:
П: Як правильно обробити `DbUpdateConcurrencyException`, коли потрібно реалізувати стратегію "Store Wins" або "Client Wins"?

В: Через об'єкт винятку: `var entry = ex.Entries.Single();`. Для стратегії "Store Wins" (перемагає база) викликають `entry.Reload()`. Для стратегії "Client Wins" актуалізують оригінальні значення з бази `entry.OriginalValues.SetValues(databaseValues)` і повторюють `SaveChanges()`.

20. Хмарні моделі: IaaS проти PaaS проти SaaS. Зони відповідальності.

↑ До змісту
Коротка суть: IaaS — оренда «віртуального заліза» (ви самі адмініструєте ОС). PaaS — готова платформа виконання (ви деплоїте тільки код додатку). SaaS — готовий софт як послуга через браузер.

Розподіл зон відповідальності:

  • IaaS (Infrastructure as a Service):
    • Приклади: AWS EC2, Azure Virtual Machines, DigitalOcean Droplets.
    • Хмара керує: Фізичні сервери, мережеве обладнання, дискові сховища, гіпервізор.
    • Ви керуєте: Встановлення ОС, патчі безпеки Windows/Linux, встановлення .NET Runtime, налаштування фаєрволів та бекапів.
  • PaaS (Platform as a Service):
    • Приклади: Azure App Service, AWS Elastic Beanstalk, Heroku.
    • Хмара керує: Усім залізом, операційною системою, оновленнями безпеки, масштабуванням (auto-scaling) та рантаймом .NET.
    • Ви керуєте: Тільки власним програмним кодом та налаштуваннями конфігурації.
  • SaaS (Software as a Service):
    • Приклади: Microsoft 365, Google Workspace, GitHub, Jira.
    • Ви користуєтеся: Готовим додатком через вебінтерфейс. Уся інфраструктура прихована.
Підступні питання на співбесіді:
П: До якої категорії належать безсерверні обчислення Serverless (Azure Functions / AWS Lambda)?

В: Це спеціалізований підвид PaaS, який часто виділяють як FaaS (Function as a Service). Головна відмінність від звичайного PaaS — автоматичне масштабування до нуля (Scale to Zero) та оплата суто за мілісекунди виконання конкретного коду.
