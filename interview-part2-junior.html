1. Різниця між `Array`, `ArrayList` та `List`. Як влаштований `List` під капотом? Що таке Capacity?

↑ До змісту
Коротка суть: Масив фіксованого розміру. `ArrayList` — застарілий нетипізований список (boxing/unboxing). `List` — обгортка над звичайним масивом, який автоматично подвоюється при переповненні.

Розгорнута відповідь:

  • T[] (Масив): Має фіксовану довжину, виділену в пам'яті один раз. Елементи лежать у пам'яті послідовно (найшвидший доступ за індексом $O(1)$).
  • ArrayList: Застарілий клас із .NET 1.1. Зберігає все як object. Будь-яке додавання int викликає boxing. Сьогодні не використовується!
  • List<T>: Типізований динамічний список. Під капотом має звичайний масив T[] _items.
    • Count — кількість реально доданих елементів.
    • Capacity — реальний розмір внутрішнього масиву (за замовчуванням: 0, 4, 8, 16, 32...).
    • Що відбувається при перевищенні Capacity: Створюється новий масив удвічі більшого розміру, всі старі елементи копіюються туди, а старий масив віддається на збір сміття GC. Операція додавання займає амортизований час $O(1)$, але при розширенні — $O(N)$.

2. Як влаштований `Dictionary` під капотом? Що таке хеш-колізія і як вона вирішується?

↑ До змісту
Коротка суть: Хеш-таблиця на основі двох масивів: `buckets` (індекси) та `entries` (дані). Пошук за $O(1)$. Колізія вирішується методом ланцюжків (внутрішній зв'язаний список за індексами).

Розгорнута відповідь:

Для збереження пари ключ-значення Dictionary робить таке:

  1. Викликає key.GetHashCode() та вираховує індекс бакета: bucketIndex = hash % buckets.Length.
  2. Зберігає запис у масив Entry[] (містить хеш, ключ, значення та індекс наступного елемента next).

Хеш-колізія виникає у двох випадках: 1) Різні ключі видали однаковий `GetHashCode()`; 2) Різні хеші після взяття залишку від ділення дали однаковий номер бакета.

Як C# вирішує колізію: Метод ланцюжків (Chaining). У бакет кладеться посилання на останній доданий елемент, а його поле next вказує на попередній. При пошуку перевіряється точний хеш, а потім викликається Equals().

Вимога: Якщо ви перевизначаєте Equals() у своєму класі, ви зобов'язані узгоджено перевизначити і GetHashCode()!

3. Ієрархія інтерфейсів колекцій: `IEnumerable`, `ICollection`, `IList`. У чому різниця?

↑ До змісту
Коротка суть: `IEnumerable` — тільки послідовний перегляд (`foreach`). `ICollection` додає модифікацію (`Add`, `Remove`) та властивість `Count`. `IList` додає доступ за числовим індексом `[i]`.

Розгорнута відповідь:

  • IEnumerable<T>: Базовий інтерфейс. Має лише один метод GetEnumerator(). Дозволяє тільки бігти вперед по колекції за допомогою foreach. Не знає розміру колекції (щоб дізнатися довжину, треба пройти її всю).
  • ICollection<T> : IEnumerable<T>: Додає розмір (Count), методи редагування (Add, Remove, Clear) та перевірку наявності (Contains).
  • IList<T> : ICollection<T>: Додає індексатор (list[0]), можливість вставки за індексом (Insert) та видалення за індексом (RemoveAt).
  • IReadOnlyCollection<T> та IReadOnlyList<T>: Використовуються, коли клієнту потрібно віддати колекцію тільки на читання.

4. Що таке делегат? Стандартні узагальнені делегати: `Action`, `Func`, `Predicate`?

↑ До змісту
Коротка суть: Делегат — це безпечний покажчик на метод. `Action` нічого не повертає (`void`). `Func` обов'язково повертає значення. `Predicate` повертає `bool`.

Розгорнута відповідь:

Делегат є посилальним типом, який знає, який метод (або методи) викликати і на якому екземплярі об'єкта.

  • Action<T1, T2...>: Приймає від 0 до 16 параметрів, завжди повертає void. 
    Action<string> print = msg => Console.WriteLine(msg);
  • Func<T1, T2..., TResult>: Приймає параметри і обов'язково повертає результат (останній тип у дженерику — тип результату). 
    Func<int, int, int> sum = (a, b) => a + b; // приймає два int, повертає int
  • Predicate<T>: Приймає один аргумент і завжди повертає bool (аналог Func<T, bool>). Зазвичай використовується в List.Find. 
    Predicate<int> isEven = x => x % 2 == 0;

5. Що таке подія (`event`)? Чим вона відрізняється від звичайного публічного поля-делегата?

↑ До змісту
Коротка суть: `event` — це захисна обгортка над делегатом (як властивість над полем). Ззовні дозволені лише оператори підписки `+=` та відписки `-=`.

Розгорнута відповідь:

Якщо зробити поле-делегат публічним: public Action OnChange;, будь-який зовнішній клас зможе:

  1. Випадково затерти всіх інших підписників, написавши obj.OnChange = MyHandler; замість +=.
  2. Викликати подію напряму ззовні: obj.OnChange();, коли це має робити тільки сам власник.

Ключове слово event обмежує права зовнішнього коду: клієнти можуть тільки підписуватися (+=) або відписуватися (-=). Смикати виклик події може виключно той клас, у якому вона оголошена.

6. Що таке анонімні методи та лямбда-вирази?

↑ До змісту
Коротка суть: Спосіб передати блок коду або метод як параметр прямо на місці виклику без необхідності виносити його в окремий іменований метод класу.

Розгорнута відповідь:

Еволюція синтаксису C#:

// 1. C# 2.0: Анонімний метод через ключове слово delegate
button.Click += delegate(object sender, EventArgs e) { Console.WriteLine("Click!"); };

// 2. C# 3.0+: Лямбда-вираз через стрілочний оператор =>
button.Click += (sender, e) => Console.WriteLine("Click!");

Лямбда-вирази діляться на:

  • Expression Lambda: Має один вираз праворуч: x => x * 2 (результат повертається автоматично).
  • Statement Lambda: Має блок інструкцій у фігурних дужках: (x, y) => { int res = x + y; return res; }.

7. Що таке LINQ? Чим відрізняється відкладене (Deferred) виконання від негайного (Immediate)?

↑ До змісту
Коротка суть: LINQ — уніфікована мова запитів до колекцій. Відкладене виконання виконує запит лише в момент обходу (в `foreach`). Негайне — одразу генерує результат (`ToList()`, `Count()`).

Розгорнута відповідь:

var numbers = new List<int> { 1, 2, 3 };

// ВІДКЛАДЕНЕ (Deferred): запит лише побудований, фільтрація ще НЕ запускалася!
var query = numbers.Where(n => n > 1); 

numbers.Add(4); // Змінили початкову колекцію

// НЕГАЙНЕ (Immediate): виконання відбувається прямо зараз під час ітерації
foreach (var n in query) 
{
    Console.WriteLine(n); // Виведе 2, 3 і 4! (бо запит спрацював після додавання)
}

Які методи форсують негайне виконання:

  • Перетворення в колекції: ToList(), ToArray(), ToDictionary().
  • Агрегатні функції: Count(), Sum(), Average(), Min(), Max().
  • Вибірка одного елемента: First(), FirstOrDefault(), Single().

8. У чому принципова різниця між `IEnumerable` та `IQueryable`?

↑ До змісту
Коротка суть: `IEnumerable` фільтрує дані в пам'яті програми (підходить для локальних колекцій). `IQueryable` перекладає запит у SQL-код і фільтрує дані на боці сервера бази даних.

Розгорнута відповідь:

  • IEnumerable<T> (простір System.Collections.Generic):
    • Працює з даними, що вже завантажені в оперативну пам'ять процесу.
    • Методи приймають звичайні делегати Func<T, bool>.
    • Якщо написати db.Users.AsEnumerable().Where(u => u.Age > 18), база вивантажить всіх мільйон користувачів через мережу, а фільтрація виконається в C#.
  • IQueryable<T> (простір System.Linq):
    • Призначений для віддалених джерел даних (Entity Framework, бази даних).
    • Методи приймають дерева виразів (Expression Trees): Expression<Func<T, bool>>.
    • EF Core аналізує дерево виразів і перетворює його на конструкцію SELECT ... WHERE Age > 18 прямо в SQL-запит. На клієнт приїдуть лише відфільтровані рядки.

9. Обробка винятків: різниця між `throw` та `throw ex`? Чи завжди спрацьовує `finally`? Що таке фільтри винятків (`when`)?

↑ До змісту
Коротка суть: `throw` зберігає повний StackTrace; `throw ex` затирає історію і робить поточний рядок початком помилки. `finally` виконується завжди (крім падіння процесу).

Розгорнута відповідь:

try 
{ 
    SomeOperation(); 
}
catch (Exception ex)
{
    Log(ex);
    throw;    // ПРАВИЛЬНО: прокидає виняток вище, зберігаючи початковий стек викликів
    // throw ex; // КАТАСТРОФА: перезаписує StackTrace, справжній рядок аварії буде втрачено!
}

Чи завжди спрацьовує finally? Практично завжди, навіть якщо в try стоїть return. Блок НЕ виконається лише в екстремальних випадках: примусове вбивство процесу ОС (Environment.FailFast() або kill -9) чи аварійний Overflow стеку (StackOverflowException).

Фільтри винятків (when): Дозволяють перехоплювати помилку лише за виконання умови без розгортання стеку:

catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
{
    Console.WriteLine("Ресурс не знайдено 404");
}

10. Керовані та некеровані ресурси. Навіщо потрібен `IDisposable` та конструкція `using`?

↑ До змісту
Коротка суть: Garbage Collector вміє звільняти тільки керовану пам'ять .NET. Некеровані ресурси (файли, підключення до БД, сокети ОС) треба закривати вручну через `Dispose()`.

Розгорнута відповідь:

  • Керовані (Managed): Об'єкти C#, виділені в купі. Ними автоматично опікується GC.
  • Некеровані (Unmanaged): Дескриптори файлів Windows/Linux, мережеві сокети, дескриптори вікон, підключення до БД. GC про них нічого не знає і не закриє їх вчасно.

Для детермінованого (негайного) звільнення ресурсів клас реалізує IDisposable з методом Dispose(). Щоб гарантовано викликати його навіть при виникненні винятків, використовують using:

// Сучасний using statement (C# 8+)
using var stream = new FileStream("data.txt", FileMode.Open);
// В кінці видимості методу автоматично викличеться stream.Dispose()!

11. Як виконується C# код? Що таке CLR, IL-код та JIT-компілятор?

↑ До змісту
Коротка суть: C# код компілюється Roslyn'ом у проміжний байт-код (IL). Під час запуску програми віртуальна машина CLR компілює IL у машинний код процесора за допомогою JIT (Just-In-Time).

Ланцюжок виконання:

  1. Вихідний код C# компілюється компілятором Roslyn у файл збірки (.dll або .exe).
  2. Всередині збірки лежить IL (Intermediate Language) — платформонезалежний байт-код + метадані типів.
  3. При запуску програми стартує CLR (Common Language Runtime) — віртуальне середовище виконання .NET.
  4. JIT-компілятор (Just-In-Time): компілює інструкції IL у реальний нативний код процесора (x86, x64, ARM) «на льоту» прямо перед першим викликом конкретного методу. Наступні виклики виконують уже скомпільований нативний код.

12. Життєві цикли сервісів у вбудованому Dependency Injection (.NET): `Transient`, `Scoped`, `Singleton`?

↑ До змісту
Коротка суть: `Transient` — новий об'єкт на кожен запит. `Scoped` — один екземпляр на один HTTP-запит. `Singleton` — один єдиний об'єкт на весь час роботи додатку.

Порівняння життєвих циклів:

  • AddTransient<IService, Service>():
    Створюється заново кожного разу, коли його хтось запитує через конструктор. Найкраще підходить для легковагих сервісів без збереження стану.
  • AddScoped<IService, Service>():
    Створюється один екземпляр на весь життєвий цикл одного веб-запиту (Scope). Всі контролери чи сервіси всередині одного HTTP-запиту отримають однаковий екземпляр. Наприклад: DbContext в EF Core за замовчуванням є саме Scoped.
  • AddSingleton<IService, Service>():
    Створюється рівно один раз при першому зверненні і живе до вимкнення сервера. Повинен бути обов'язково потокобезпечним (thread-safe). Наприклад: сервіс локального in-memory кешування.

13. Що таке REST API? Основні HTTP-методи та найважливіші статусні коди відповідей.

↑ До змісту
Коротка суть: REST — архітектурний стиль передачі стану за допомогою стандартного протоколу HTTP. Статуси: 2xx — успіх, 4xx — помилка клієнта, 5xx — помилка сервера.

Основні HTTP методи:

  • GET: Отримання ресурсу. Не повинен змінювати стан на сервері (ідемпотентний).
  • POST: Створення нового ресурсу. Неідемпотентний.
  • PUT: Повне оновлення ресурсу (або створення з вказаним ID). Ідемпотентний.
  • PATCH: Часткове оновлення окремих полів ресурсу.
  • DELETE: Видалення ресурсу. Ідемпотентний.

Популярні HTTP статуси:

  • 200 OK: Успішний запит. | 201 Created: Ресурс успішно створено (відповідь на POST). | 204 No Content: Успіх, але тіло порожнє (часто для DELETE).
  • 400 Bad Request: Невалідне тіло або параметри запиту.
  • 401 Unauthorized: Користувач не автентифікований (не надав валідний токен).
  • 403 Forbidden: Користувача розпізнано, але у нього недостатньо прав (ролей) для цієї дії.
  • 404 Not Found: Запитуваний ресурс не існує.
  • 500 Internal Server Error: Необроблена аварія або виняток на бекенді.

14. Реляційні бази даних для Junior: PK, FK, різниця між `INNER JOIN` та `LEFT JOIN`, навіщо потрібні індекси?

↑ До змісту
Коротка суть: PK — унікальний ідентифікатор рядка. FK — посилання на іншу таблицю. INNER JOIN повертає лише спільні збіги, LEFT JOIN повертає ВСІ рядки лівої таблиці + відповідності з правої. Індекс прискорює пошук з $O(N)$ до $O(\log N)$.

Розгорнута відповідь:

  • Primary Key (PK): Первинний ключ. Унікальне непорожнє значення (зазвичай Id: int або Guid), що ідентифікує конкретний запис.
  • Foreign Key (FK): Зовнішній ключ. Поле, що посилається на PK іншої таблиці, забезпечуючи зв'язки між сутностями.
  • Різниця JOIN'ів:
    • INNER JOIN: Повертає тільки ті рядки, для яких знайдено збіг в обох таблицях.
    • LEFT (OUTER) JOIN: Повертає всі записи з лівої таблиці. Якщо для запису зліва в правій таблиці збігу не знайдено, поля правої таблиці заповнюються значеннями NULL.
  • Індекси: Спеціальні допоміжні структури (найчастіше B-Tree дерева). Без індексу СУБД робить Full Table Scan (перебирає кожен рядок таблиці $O(N)$). Індекс дозволяє миттєво знаходити записи за логарифмічний час $O(\log N)$. Плата: сповільнює операції запису (`INSERT`, `UPDATE`), бо дерево індексу потрібно перебудовувати.

15. Що таке Unit-тести? Патерн Arrange-Act-Assert (AAA) та Mock-об'єкти.

↑ До змісту
Коротка суть: Тестування одного маленького методу в повній ізоляції від бази/мережі. Структура: підготовка даних (Arrange), виклик (Act), перевірка очікувань (Assert). Залежності замінюються на «заглушки» (Mock).

Розгорнута відповідь:

Unit-тест перевіряє правильність логіки одного класу або методу. Він має виконуватися за мілісекунди і не повинен ходити в реальну базу даних чи зовнішні HTTP API.

[Fact]
public void CalculateDiscount_ForVipUser_ShouldReturn20Percent()
{
    // 1. Arrange (Підготовка даних та залежностей)
    var calculator = new DiscountService();
    decimal amount = 100m;

    // 2. Act (Виконання досліджуваної дії)
    decimal discount = calculator.Calculate(amount, isVip: true);
